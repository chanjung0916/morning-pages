## 🎬 오프닝 — 비전 제시 (30초)

> *[앱 홈 화면 보여주며 시작]*

"여러분, 오늘 아침에 일어나서 제일 먼저 한 일이 무엇인가요?
아마 스마트폰을 켜서 SNS나 뉴스를 확인하셨을 거예요.

저는 다른 걸 제안하고 싶었습니다.
**하루를 시작하기 전, 단 2~3분, 오늘의 나를 내가 정하는 시간.**

이것이 Morning Pages입니다."

## 📌 문제 정의 (30초)

"일기를 쓰고 싶어도 이런 장벽들이 있습니다.
종이 일기는 매일 들고 다니기 불편하고,
일반 메모앱은 감성이 없고,
가장 큰 문제는 — **'무엇을 써야 할지 모른다'**는 거예요.

빈 화면 앞에서 멈추는 경험, 다들 있으시죠?
Morning Pages는 AI가 생성한 주제로 그 빈 화면을 채워줍니다."

---

## 📋 프로젝트 계획 (30초)

"14주 개발 일정을 WBS로 관리했습니다.

- 1~2주: 기획 및 아키텍처 설계
- 3~6주: 핵심 CRUD + 주제 시스템 구현
- 7~10주: UI 개선, 캘린더, 즐겨찾기, 기록 화면
- 11~12주: 알림, 설정, 다크모드
- 13~14주: 테스트, 문서화, 발표 준비

기술 스택은 React Native + Expo SDK 54, TypeScript, AsyncStorage입니다."

---

## 🏗 아키텍처 & 구현 방법 (45초)

"앱 구조는 **Layered Architecture + MVVM** 패턴을 따릅니다.

```
Presentation → Application → Domain → Data
```

화면(Presentation)은 Context(Application)를 통해 데이터를 받고,
비즈니스 규칙은 UseCase(Domain)에 격리되어 있습니다.
실제 저장은 AsyncStorage(Data)에서 담당합니다.

이 구조 덕분에 두 가지를 얻었습니다.
첫째, **Domain 레이어를 React Native 없이 Jest로 단위 테스트** 가능했습니다.
둘째, **AI Agent인 Claude Code와 협업 시 파일 위치 혼선이 없었습니다.**
AGENTS.md에 레이어 경계 규칙을 명시해 두고, Agent가 이를 참조하도록 했습니다."

---

## ⚙️ 구현 시행착오 (30초)

"개발 중 세 가지 큰 시행착오가 있었습니다.

첫째, expo-notifications가 Expo Go에서 로드 시 에러를 발생시켰습니다.
→ dynamic import로 Expo Go 환경에서만 우회 처리했습니다.

둘째, ContributionGraph 툴팁이 overflow:hidden 안에 갇혀 잘렸습니다.
→ 툴팁을 ScrollView 바깥으로 꺼내 절대 좌표로 렌더링했습니다.

셋째, AsyncStorage vs SQLite 선택 문제.
→ 일기 앱 규모에서 복잡한 쿼리가 불필요하다 판단, AsyncStorage로 결정. (ADR-001에 기록)"

## 🎯 활용 방안 (20초)

"이 앱은 세 가지 방향으로 발전할 수 있습니다.

하나, **AI 주제 생성 자동화** — 현재는 ChatGPT/Claude에 프롬프트를 복사-붙여넣기 하지만, API 직접 연동으로 원탭 생성 가능.

둘, **클라우드 동기화** — 지금은 기기 내 저장이지만 로그인 추가 시 기기 간 공유 가능.

셋, **습관 통계 대시보드** — 연속 작성일, 주제별 분포 분석."

## 🎥 시연 데모 (30초)

> *[앱을 실기기에서 직접 시연]*

**시나리오:**
1. 홈 화면 → 오늘 일기 쓰기 버튼 탭
2. 주제 카드 확인 ("오늘 하루 이것 하나만 이룬다면?")
3. 한 문장 입력 → 저장
4. 홈으로 돌아와 잔디 그래프에 오늘 칸 채워진 것 확인
5. 사이드 메뉴 → 캘린더에서 오늘 날짜 점 확인

## ❓ 질의응답 준비

### Q1. 앱 구조는 어떻게 되어 있나요?
> "Presentation → Application → Domain → Data 4계층입니다.
> `src/presentation/screens/`에 화면,
> `src/application/context/`에 상태 관리,
> `src/domain/usecases/`에 비즈니스 규칙,
> `src/data/repositories/`에 AsyncStorage 연동 코드가 있습니다.
> 단방향 의존으로 각 레이어가 분리되어 있습니다."

### Q2. 개발 환경 설정은 어떻게 하나요?
> "Node.js 20 LTS와 Expo CLI만 있으면 됩니다.
> `git clone` → `npm install` → `npx expo start` 세 단계로 5분 안에 실행됩니다.
> 자세한 내용은 docs/setup.md에 정리했습니다."

### Q3. 빌드와 배포는 어떻게 하나요?
> "개발 중에는 Expo Go 앱으로 QR 코드 스캔 후 실시간 확인합니다.
> 배포는 EAS Build를 사용합니다. `eas build --platform android --profile preview` 명령 하나로
> 클라우드에서 APK가 자동 생성됩니다. 개발 PC에 Android SDK가 없어도 됩니다.
> 자세한 내용은 docs/deploy.md에 있습니다."

### Q4. ADR이 무엇인가요? 어떤 결정을 기록했나요?
> "ADR은 Architecture Decision Record, 아키텍처 의사결정 기록입니다.
> 왜 이 기술을 선택했는지 나중에 추적할 수 있도록 기록합니다.
> 저는 3개를 작성했습니다.
> ADR-001: AsyncStorage 선택 이유 (오프라인 우선, 개인정보 보호),
> ADR-002: Expo Managed Workflow 채택 (빠른 개발, EAS 빌드 자동화),
> ADR-003: Layered Architecture 채택 (테스트 용이, 변경 격리)."
