# 6주 개발 일정 — 아침 일기 (Morning Pages)

> 기간: 10주차 ~ 14주차 (개발) + 15주차 (최종 발표)
> 중간 발표: 12주차 | 최종 발표: 15주차

---

## 주차별 일정

### 10주차 — 환경 설정 & 기획 완료

| 항목 | 내용 |
|---|---|
| 목표 | 개발 환경 구축 및 프로젝트 뼈대 완성 |
| 산출물 | Expo 프로젝트 초기화, GitHub 리포지토리, `.planning/` 문서 완비 |
| 작업 | Node.js/Expo CLI 설치, 프로젝트 생성, 네비게이션 설치, 폴더 구조 설계, ADR 작성 |
| 검증 | `npx expo start` 실행 시 에뮬레이터에서 기본 화면 표시 |

---

### 11주차 — 핵심 기능 개발 (Must)

| 항목 | 내용 |
|---|---|
| 목표 | 일기 CRUD 완성 |
| 산출물 | 홈 화면, 작성 화면, 목록 화면, 상세 화면, 로컬 저장소 서비스 |
| 작업 | 데이터 모델 정의, AsyncStorage CRUD 구현, 화면 4개 개발, 네비게이션 연결 |
| 검증 | 일기 작성 → 저장 → 목록 조회 → 상세 보기 → 수정 → 삭제 흐름 정상 동작 |

---

### 12주차 — 중간 발표 & 추가 기능 시작

| 항목 | 내용 |
|---|---|
| 목표 | 중간 발표 + 기분 기록 기능 개발 시작 |
| 산출물 | 중간 발표 자료 (`docs/presentation/interim.md`), 이모지 기분 선택 UI |
| 작업 | 발표 자료 준비, 데모 시나리오 구성, 기분 컴포넌트 구현 |
| 검증 | 중간 발표 데모 정상 시연 가능 |

> **중간 발표 포인트:** Must 기능 동작 데모 + 아키텍처 설명 + 남은 일정 공유

---

### 13주차 — 추가 기능 개발 (Should)

| 항목 | 내용 |
|---|---|
| 목표 | 캘린더 뷰, 푸시 알림 구현 |
| 산출물 | 캘린더 화면, 알림 설정 화면 |
| 작업 | react-native-calendars 연동, 일기 작성일 dot 표시, Expo Notifications 설정, 알림 스케줄링 |
| 검증 | 캘린더에서 날짜 탭 시 해당 일기 조회, 지정 시간에 알림 수신 확인 |

---

### 14주차 — UI 완성 & 테스트

| 항목 | 내용 |
|---|---|
| 목표 | UI/UX 완성도 향상 및 전체 테스트 |
| 산출물 | 완성된 앱, 테스트 결과, `docs/` 문서 완비 |
| 작업 | 빈 상태 UI, 오류 처리, 다크 모드 대응, 오프라인 검증, EAS Build APK 생성 |
| 검증 | 실기기(Android/iOS)에서 전체 기능 정상 동작, 오프라인 테스트 통과 |

---

### 15주차 — 최종 발표

| 항목 | 내용 |
|---|---|
| 목표 | 최종 발표 및 데모 시연 |
| 산출물 | 최종 발표 자료 (`docs/presentation/final.md`), 완성된 GitHub 리포지토리 |
| 작업 | 발표 자료 완성, 데모 데이터 준비, Q&A 대비 백업 슬라이드 작성 |
| 검증 | 12분 발표 + 데모 시연 성공 |

---

## 마일스톤 요약

| 주차 | 마일스톤 |
|---|---|
| 10주차 말 | 개발 환경 완료, 기획 문서 완비 |
| 11주차 말 | Must 기능(CRUD) 완성 |
| 12주차 | **중간 발표** |
| 13주차 말 | Should 기능(캘린더, 알림) 완성 |
| 14주차 말 | 테스트 완료, APK 빌드 성공 |
| 15주차 | **최종 발표** |

## 위험 요소 및 대응 방안

| # | 위험 요소 | 발생 가능성 | 영향도 | 대응 방안 |
|---|---|---|---|---|
| 1 | Expo 환경 설정 오류 (Windows/Mac 차이) | 높음 | 높음 | 공식 문서 기준으로 설치, Expo Go 앱으로 우선 테스트 |
| 2 | 푸시 알림 iOS 시뮬레이터 미지원 | 중간 | 중간 | Android 에뮬레이터 또는 실기기로 테스트, 발표 시 영상 대체 |
| 3 | 개발 일정 지연 (기능 과다) | 중간 | 높음 | Should/Could 기능은 Must 완성 후 착수, 우선순위 엄수 |
| 4 | AsyncStorage 데이터 마이그레이션 이슈 | 낮음 | 중간 | 초기 데이터 모델 설계 신중히, 스키마 변경 최소화 |
| 5 | 발표 당일 데모 앱 오류 | 낮음 | 높음 | 발표 전날 APK 빌드 완료, 화면 녹화 영상 백업 준비 |
