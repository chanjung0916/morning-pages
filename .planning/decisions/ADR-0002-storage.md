# ADR-0002: 데이터 저장소 선택

## Status

Accepted

## Context

일기 데이터를 기기에 저장해야 한다.
앱은 인터넷 연결 없이도 완전히 동작해야 하며, 백엔드 서버는 구축하지 않는다.
사용자 데이터는 기기 밖으로 전송되지 않아야 한다.

## Decision

**AsyncStorage (@react-native-async-storage/async-storage)** 를 사용한다.

## Alternatives

| 대안 | 검토 결과 |
|---|---|
| Firebase Firestore | 실시간 동기화, 다기기 지원. 단, 모든 읽기·쓰기가 네트워크 왕복을 거치며 오프라인 쓰기는 로컬 캐시에 보류 후 재연결 시 동기화되는 구조라 별도 충돌 처리 필요 |
| SQLite (expo-sqlite) | 관계형 쿼리, 복잡한 데이터 구조에 적합. 단, 키-값 저장 수준의 일기 데이터에는 스키마 정의와 SQL 작성이 오버스펙 |
| MMKV | 동기 API로 성능 우수. 단, C++ native module이라 Expo managed workflow에서 추가 설정 필요 |


- 모든 읽기·쓰기가 로컬에서 처리되어 네트워크 상태와 무관하게 일정한 응답 속도 보장
- Expo managed workflow와 추가 설정 없이 호환
- 사용자 데이터가 기기 밖으로 전송되지 않음


## 60초 발표 요약

"데이터 저장은 AsyncStorage를 선택했습니다.
AsyncStorage는 기기 내 키-값 저장소로, 읽기·쓰기가 완전히 로컬에서 처리되어
네트워크 상태와 무관하게 항상 일정한 응답 속도를 보장합니다.
대안인 Firebase는 실시간 동기화와 다기기 지원이 강점이지만,
오프라인 상태에서 쓴 데이터는 로컬 캐시에 보류됐다가 재연결 시 동기화되는 구조라
아침 일기는 개인 기기에서만 쓰는 데이터이고 실시간 동기화가 필요 없어
로컬 저장만으로 충분하다고 판단했습니다."
